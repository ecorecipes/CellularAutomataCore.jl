Spaces, rules and states

Lattices and their boundaries, neighbourhoods, local rules, counter-based randomness, environmental fields, states and the model layer.

Spaces and boundaries

CellularAutomataCore.AbstractSpace — Type
AbstractSpace

Supertype of the spaces cells live in: Lattice (square or hexagonal, any number of dimensions, built by Torus, Grid and HexGrid) and GraphSpace.

source
CellularAutomataCore.Lattice — Type
Lattice{N,G,B}

A regular N-dimensional lattice of prod(dims) cells with geometry G (Square or Hex) and one boundary condition per axis. A state on it is an Array of size dims, or a NamedTuple of such arrays (one per layer). Build one with Torus, Grid or HexGrid.

source
CellularAutomataCore.Torus — Function
Torus(dims...)
Torus(dims::Tuple)

A square lattice that is periodic on every axis: a ring in one dimension, a torus in two.

julia> Torus(5, 4)
Torus((5, 4))
source
CellularAutomataCore.Grid — Function
Grid(dims...; boundary=Constant(0))

A square lattice with edges. boundary is one AbstractBoundary for every axis or a tuple with one per axis; Grid(64, 64; boundary=(Periodic(), Constant(0))) is a cylinder.

source
CellularAutomataCore.HexGrid — Function
HexGrid(nq, nr; boundary=Periodic())

A two-dimensional lattice of hexagonal cells in axial coordinates (see Hex): a parallelogram of nq × nr cells, periodic by default.

source
CellularAutomataCore.GraphSpace — Type
GraphSpace(neighbours::Vector{Vector{Int}})
GraphSpace(n, edges; directed=false)

An irregular space of n cells in which cell i reads the cells neighbours[i], in that order: patches of a metapopulation, trees at measured positions, fields connected by roads. A state on it is a Vector of length n (or a NamedTuple of them). The second form builds the lists from an edge list of (i, j) pairs; undirected edges are added in both directions.

julia> ring = GraphSpace(4, [(1, 2), (2, 3), (3, 4), (4, 1)]);

julia> ring.neighbours[1]
2-element Vector{Int64}:
 2
 4

CellularAutomataCore.Hex — Type
Hex()

Hexagonal cells in axial coordinates: cell (q, r) is stored at index [q, r] and its six nearest neighbours are at offsets (±1, 0), (0, ±1), (1, -1) and (-1, 1). Pointy-top hexagons with centres at x = √3 (q + r / 2), y = 1.5 r.

AbstractBoundary

Supertype of the boundary conditions of a Lattice axis: Periodic, Reflecting and Constant.

source
CellularAutomataCore.Periodic — Type
Periodic()

The axis wraps around: the cell beyond the last is the first.

source
CellularAutomataCore.Reflecting — Type
Reflecting()

The axis is mirrored at its edges, with the edge cell repeated: on an axis of length n, index 0 reads cell 1, index -1 reads cell 2, and index n + 1 reads cell n.

source
CellularAutomataCore.Constant — Type
Constant(value)

Every cell beyond the edge holds value, for example Constant(0) for a dead or empty margin. When cells lie beyond the edges of several Constant axes at once, the value of the highest-numbered of those axes is used.

Neighbourhoods

CellularAutomataCore.AbstractNeighbourhood — Type
AbstractNeighbourhood

Supertype of neighbourhoods: Moore, VonNeumann, Hexagonal, Offsets and GraphNeighbours. The centre cell is never part of a neighbourhood: a local rule receives it separately.

source
CellularAutomataCore.Moore — Type
Moore(radius=1)

All cells within Chebyshev distance radius on a square lattice of any dimension: 8 cells in two dimensions at radius 1, 24 at radius 2.

source
CellularAutomataCore.VonNeumann — Type
VonNeumann(radius=1)

All cells within Manhattan distance radius on a square lattice of any dimension: 4 cells in two dimensions at radius 1, 12 at radius 2.

source
CellularAutomataCore.Hexagonal — Type
Hexagonal(radius=1)

All cells within hexagonal distance radius on a HexGrid: 6 cells at radius 1, 18 at radius 2.

source
CellularAutomataCore.Offsets — Type
Offsets(offsets...)

An explicit neighbourhood on a lattice: the cells at the given offsets from the centre, in the given order. Offsets are CartesianIndexes or tuples of integers; the zero offset (the centre) is not allowed and duplicates are rejected. Every other lattice neighbourhood is resolved into an Offsets, see neighbourhood_offsets. Iterating over an Offsets gives the offsets as CartesianIndexes, in order.

julia> Offsets((-1, 0), (1, 0))  # the cells above and below
Offsets((-1, 0), (1, 0))

julia> collect(Offsets((-1, 0), (1, 0)))
2-element Vector{CartesianIndex{2}}:
 CartesianIndex(-1, 0)
 CartesianIndex(1, 0)
source
CellularAutomataCore.GraphNeighbours — Type
GraphNeighbours()

The neighbourhood of a GraphSpace: each cell reads the cells listed for it in the graph. It is the default neighbourhood of a graph space and is meaningless on a lattice.

source
CellularAutomataCore.default_neighbourhood — Function
default_neighbourhood(space)

The neighbourhood a rule uses when it does not name one: Moore(1) on a square lattice, Hexagonal(1) on a hexagonal one and GraphNeighbours() on a GraphSpace.

source
CellularAutomataCore.neighbourhood_offsets — Function
neighbourhood_offsets(neighbourhood, space) -> Offsets

Resolve a neighbourhood on a lattice into explicit Offsets, in column-major order of the offsets (first axis fastest). For a one-dimensional Moore(r) this is -r, …, -1, 1, …, r, left to right. Raises IncompatibleSpaceError for a neighbourhood that does not fit the space, such as Moore on a hexagonal grid or offsets of the wrong dimension.

julia> neighbourhood_offsets(VonNeumann(1), Torus(8, 8))
Offsets((0, -1), (-1, 0), (1, 0), (0, 1))

Rules

CellularAutomataCore.AbstractRule — Type
AbstractRule

Supertype of rules. A rule implements

  • local_rule(rule, cell, nbrs, ctx): the next state of a cell, given its state cell, the states nbrs of its neighbours (a tuple on a lattice, in the order of neighbourhood_offsets; a vector on a GraphSpace) and a CellContext ctx;
  • neighbourhood(rule): the AbstractNeighbourhood it reads, or nothing for the space's default_neighbourhood;

and optionally validate_state(rule, u0), which checks an initial state once.

source
CellularAutomataCore.local_rule — Function
local_rule(rule, cell, nbrs, ctx)

The next state of a cell under rule; see AbstractRule. The result is converted to the element type of the state (for a layered state, it is a NamedTuple with one value per layer).

source
CellularAutomataCore.neighbourhood — Function
neighbourhood(rule)

The neighbourhood rule reads, or nothing for the default neighbourhood of the space it runs on.

source
CellularAutomataCore.validate_state — Function
validate_state(rule, u0)

Check that every value of the initial state u0 can be read by rule, raising InvalidStateError otherwise. Called once by CAProblem; the default accepts every state.

source
CellularAutomataCore.LocalRule — Type
LocalRule(f, neighbourhood=nothing; states=nothing)

A rule given by a function f(cell, nbrs, ctx) returning the next state of a cell (see AbstractRule for the arguments). neighbourhood is any AbstractNeighbourhood, or nothing for the space's default. If states is a collection, every value of an initial state must be in it.

States can be integers, Bools, Symbols, isbits structs, or (for a layered state) NamedTuples with one value per layer. Random numbers come from uniform(ctx, k) and bernoulli(ctx, p, k).

julia> majority = LocalRule(VonNeumann(1)) do cell, nbrs, ctx
           s = cell + sum(nbrs)
           s >= 3 ? one(cell) : zero(cell)
       end;

julia> u = solve(CAProblem(majority, Int8[0 1 0; 1 1 0; 0 0 0], 1)).u[end];

julia> u
3×3 Matrix{Int8}:
 0  0  0
 0  1  0
 0  0  0
source
CellularAutomataCore.Wolfram — Type
Wolfram(code; states=2, radius=1)

A one-dimensional rule with Wolfram's numbering: the new state of a cell is the digit of code (in base states) whose position is the window of states, read left to right as a base-states number. radius is r for the window -r:r, or a tuple (left, right) for an asymmetric window. Wolfram(30) and Wolfram(110) are the elementary rules; Wolfram(code; states=3) is a three-colour rule. Runs on one-dimensional lattices.

julia> sol = solve(CAProblem(Wolfram(90), single_seed(7), 2));

julia> sol.u[end]'
1×7 adjoint(::Vector{Int8}) with eltype Int8:
 0  1  0  0  0  1  0
source
CellularAutomataCore.Totalistic — Type
Totalistic(code; states=2, radius=1)

A one-dimensional totalistic rule with Wolfram's numbering: the new state of a cell is the digit of code (in base states) at the position given by the sum of the states in the window -radius:radius, centre included. Runs on one-dimensional lattices.

source
CellularAutomataCore.Life — Type
Life(rule="B3/S23"; neighbourhood=nothing)
Life(preset::Symbol; neighbourhood=nothing)
Life(birth, survive; neighbourhood=nothing)

A two-state outer-totalistic ("Life-like") rule. A dead cell (0) is born when the number of live neighbours (1) is in birth; a live cell survives when it is in survive. The rule can be given in B/S notation ("B36/S23"), S/B notation ("23/36"), as a name from LIFE_PRESETS, or as two collections of counts (needed for counts above 8 in large neighbourhoods, for example Life(34:45, 34:58; neighbourhood=Moore(5))). The neighbourhood defaults to the space's (Moore(1) on a square lattice, Hexagonal(1) on a hexagonal one).

julia> Life(:highlife)
Life("B36/S23")

julia> Life("23/3")
Life("B3/S23")
source
CellularAutomataCore.Generations — Type
Generations(rule; neighbourhood=nothing)
Generations(preset::Symbol; neighbourhood=nothing)

A Generations rule with C states: 0 is dead, 1 alive and 2:C-1 dying. A dead cell is born when its number of live neighbours is in birth; a live cell stays alive when the number is in survive and otherwise starts dying; a dying cell advances one state per step and dies after state C - 1. Written "B2/S/C3" (Brian's Brain), "B2/S345/C4" or in S/B/C notation "345/2/4"; named rules are in GENERATIONS_PRESETS. With C = 2 it is the Life rule of the same B/S.

source
CellularAutomataCore.LIFE_PRESETS — Constant
LIFE_PRESETS

Named Life rules: :conway (B3/S23), :highlife (B36/S23), :seeds (B2/S), :day_and_night (B3678/S34678), :morley (B368/S245), :two_by_two (B36/S125), :replicator (B1357/S1357), :diamoeba (B35678/S5678), :thirty_four (B34/S34), :life_without_death (B3/S012345678) and :maze (B3/S12345).

source
CellularAutomataCore.GENERATIONS_PRESETS — Constant
GENERATIONS_PRESETS

Named Generations rules: :brians_brain (B2/S/C3) and :star_wars (B2/S345/C4).

source
CellularAutomataCore.rulestring — Function
rulestring(rule)

The B/S (or B/S/C) notation of a Life or Generations rule. Counts above 8 are written as comma-separated ranges ("B34..45/S34..58"), which Life's string parser does not read back.

source
CellularAutomataCore.BlockRule — Type
BlockRule(f)

A rule for the Margolus scheme. f(block, ctx) receives the states of a 2 × 2 block as a tuple (top_left, bottom_left, top_right, bottom_right) (column-major order) and a CellContext whose index is the block's top-left cell, and returns the block's new states in the same order. Block rules model conserved, reversible or particle-like dynamics: lattice gases, sand.

source
CellularAutomataCore.EventRule — Type
EventRule(f, neighbourhood=nothing; states=nothing)

A rule given as rates: f(cell, nbrs, ctx) returns the cell's possible transitions as a tuple (or vector) of rate => new_state pairs, an empty tuple when it cannot change. The cell leaves its state at the total rate and moves to each new_state with probability proportional to its rate: a continuous-time Markov chain on the lattice. Rates must be nonnegative and finite and may read ctx.p, covariates and the neighbours' states; they must not draw random numbers.

Solve it exactly with the Gillespie scheme, with real-valued time, or in discrete time with Synchronous (or Stochastic or Checkerboard), where in each step a cell with total rate a changes with probability 1 - exp(-a), using draws k = 1 and k = 2 of uniform. states, if given, are the allowed values of the initial state.

julia> sis = EventRule(VonNeumann(1)) do cell, nbrs, ctx
           cell == 0 ? (0.5 * count(==(1), nbrs) => 1,) : (1.0 => 0,)
       end;

julia> sis.f(0, (1, 1, 0, 0), nothing)
(1.0 => 1,)
source
CellularAutomataCore.Lenia — Type
Lenia(; R=13, μ=0.15, σ=0.015, dt=0.1, peaks=(1.0,), method=:direct, precision=Float64)

The continuous Lenia rule (Chan, 2019) on states in [0, 1]. At every step each cell computes the potential U, the LeniaKernel(R; peaks) weighted mean of the states around it, and moves by dt * (2 exp(-(U - μ)² / 2σ²) - 1), clipped to [0, 1]. The potential is the rule's own KernelField named :potential; method = :fft computes it by FFT (needs using FFTW and a periodic lattice), which is much faster for the usual radius of 13. precision = Float32 runs the rule and its field in single precision (for Apple GPUs through Metal; use a Float32 state). ORBIUM is a glider for the default parameters.

source
CellularAutomataCore.ORBIUM — Constant
ORBIUM

A 20 × 20 seed of Orbium unicaudatus, the glider of Lenia (Chan, 2019) for R = 13, μ = 0.15, σ = 0.015, dt = 0.1 (the pattern as distributed with CellIA.jl, MIT licence). Place it on an empty grid with place!.

Randomness

CellularAutomataCore.CellContext — Type
CellContext

What a local rule knows besides the states of its cell and neighbours. Fields:

  • p: the problem's parameters (NullParameters() if none were given); a callback may reassign integ.p to change them during a run;
  • index: the cell's index in its space (a CartesianIndex on a lattice, an Int on a GraphSpace);
  • t: the time of the state being read; the rule computes the state at t + 1.

Random numbers for the cell come from uniform and bernoulli, never from a global generator. Covariate layers and kernel fields are read with covariate and field.

source
CellularAutomataCore.uniform — Function
uniform(ctx::CellContext, k::Integer=1) -> Float64

The k-th uniform random number in [0, 1) for the cell and time step of ctx. The value is a pure function of the problem's seed, the cell, the time and k: the same model gives the same numbers on every backend and thread count. Use a different k ≥ 1 for every independent draw a rule makes in one step; k = 0 is reserved for the update schemes (see Stochastic).

julia> ctx = CellularAutomataCore.CellContext(nothing, CartesianIndex(1), 0, 1, 42);

julia> uniform(ctx) == uniform(ctx)
true

julia> uniform(ctx, 1) == uniform(ctx, 2)
false
source
uniform(Float32, ctx::CellContext, k::Integer=1) -> Float32

The k-th draw as a Float32 in [0, 1), with 24 random bits: for rules that run on devices without double precision, such as Apple GPUs through Metal. bernoulli uses it when the probability is a Float32.

source
CellularAutomataCore.bernoulli — Function
bernoulli(ctx::CellContext, p, k::Integer=1) -> Bool

true with probability p, using the k-th draw of uniform. The draw has the precision of p: a Float32 probability uses uniform(Float32, ctx, k), so a rule written with Float32 parameters needs no double precision.

source
CellularAutomataCore.philox4x32 — Function
CellularAutomataCore.philox4x32(counter, key) -> NTuple{4,UInt32}

The Philox4x32-10 bijection of the Random123 library (Salmon et al., 2011): ten rounds mapping a 128-bit counter::NTuple{4,UInt32} under a 64-bit key::NTuple{2,UInt32} to 128 pseudo-random bits. Allocation-free and usable inside GPU kernels. uniform builds on it.

source

Covariates, kernels and fields

CellularAutomataCore.covariate — Function
covariate(ctx::CellContext, name::Symbol)

The value of covariate name at the cell: a fixed layer if the covariate array has the size of the space, or the slice for the current time if it has one more axis (slice mod1(t + 1, nt) of nt, so it repeats every nt steps). Covariates are given to CAProblem as a NamedTuple of arrays.

source
CellularAutomataCore.field — Function
field(ctx::CellContext, name::Symbol)

The value at the cell of the KernelField name, computed from the state at the start of the current step.

source
CellularAutomataCore.fields — Function
fields(rule) -> NamedTuple

The KernelFields a rule needs, by name; CAProblem merges them with the fields it is given. The default is none. Lenia declares its potential field this way.

source
CellularAutomataCore.KernelField — Type
KernelField(kernel, source=identity; include_centre=true, method=:direct)

A field recomputed at the start of every step: at each cell I, the sum over the displacements o of kernel of weight(o) * source(state at I - o), with the state read beyond the edges according to the space's boundary conditions. The kernel is a dispersal kernel: weight(o) is the share of propagules that travel displacement o from their source, so an AnisotropicKernel pointing east spreads infection eastwards. Rules read it with field(ctx, name). source maps a cell state to a number, for example cell -> cell == :I for the density of infectious cells around each cell. Weights are normalised to sum to one (kernel_weights).

method = :fft computes the sum by fast Fourier transform, which is much faster for wide kernels; it needs using FFTW, periodic boundaries on every axis, and agrees with :direct to floating-point rounding rather than exactly. precision = Float32 stores the weights and the field in single precision, as devices without double precision (Apple GPUs through Metal) need.

source
CellularAutomataCore.kernel_weights — Function
kernel_weights(kernel, space; include_centre=true) -> (offsets, weights)

The offsets of a kernel on a lattice and their weights, normalised to sum to one. Offsets farther than the kernel's radius, or with zero weight, are left out; so is the zero offset (the cell itself) when include_centre is false.

julia> offsets, weights = kernel_weights(UniformKernel(1), Torus(5, 5));

julia> length(offsets), sum(weights)
(5, 1.0)
source
CellularAutomataCore.DispersalKernel — Type
DispersalKernel

Supertype of dispersal kernels: GaussianKernel, ExponentialKernel, PowerLawKernel, UniformKernel, LeniaKernel, AnisotropicKernel and EmpiricalKernel. A kernel gives an unnormalised weight to every offset within its radius; kernel_weights lists and normalises them.

source
CellularAutomataCore.GaussianKernel — Type
GaussianKernel(σ; radius=ceil(Int, 3σ))

Weight exp(-d² / 2σ²) at distance d, cut off at radius.

source
CellularAutomataCore.ExponentialKernel — Type
ExponentialKernel(scale; radius=ceil(Int, 5scale))

Weight exp(-d / scale) at distance d, cut off at radius: thinner-tailed than a power law, fatter than a Gaussian.

source
CellularAutomataCore.PowerLawKernel — Type
PowerLawKernel(α; radius=10)

Weight (1 + d)^(-α) at distance d, cut off at radius: a fat-tailed (Lévy-like) kernel for occasional long-distance dispersal.

source
CellularAutomataCore.UniformKernel — Type
UniformKernel(radius)

Equal weight on every cell within distance radius: a disc.

source
CellularAutomataCore.LeniaKernel — Type
LeniaKernel(R; peaks=(1.0,))

The smooth shell kernel of Lenia (Chan, 2019): with r = d / R, the shell r ∈ (0, 1) is divided into length(peaks) rings, ring i having height peaks[i] and profile exp(4 - 1 / (x (1 - x))) across it.

source
CellularAutomataCore.AnisotropicKernel — Type
AnisotropicKernel(base, direction, strength)

A base kernel tilted towards direction (radians; 0 points along increasing column index, "east", and π/2 along decreasing row index, "north", as drawn by plot): the weight at an offset making angle θ with direction is multiplied by exp(strength * cos(θ)), a von Mises tilt. Use it for wind- or slope-driven dispersal.

source
CellularAutomataCore.EmpiricalKernel — Type
EmpiricalKernel(weights::AbstractMatrix)

A two-dimensional kernel given as a matrix of weights with odd side lengths, centred on the middle entry (the cell itself): weights[i, j] is the weight of offset (i - ci, j - cj).

source

Models

A ModelingToolkit-style layer: declare a model's states, parameters, rule, fields and covariates once, then build problems by name with CAProblem(model, u0map, tspan, pmap; space).

CellularAutomataCore.CAModel — Type
CAModel(rule; name=:model, states, parameters=(;), fields=(;), covariates=(),
        description="")

A declarative cellular-automaton model, turned into a problem by CAProblem(model, u0map, tspan, pmap; space).

  • states: a NamedTuple of default values, one per state variable ((host=Int8(1), pest=0.0f0)), or a vector of StateVariables. A model with one state variable has an array state; with several, a layered NamedTuple state.
  • parameters: a NamedTuple of default values, or a vector of Parameters; the rule reads them as ctx.p.
  • fields: KernelFields by name; covariates: the names of the covariate layers the rule reads, which every problem must supply.

@camodel builds a model from a block of declarations.

source
CellularAutomataCore.@camodel — Macro
@camodel name begin
    @description "..."
    @states x::T = default [∈ domain] ...
    @parameters a = 1.0 b = 2.0 ...
    @neighbourhood Moore(1)
    @fields name = KernelField(...) ...
    @covariates c1 c2 ...
    @rule begin
        ...  # uses cell, nbrs, ctx and the parameters by name
    end
end

Build a CAModel from declarations, in the spirit of ModelingToolkit's @mtkmodel. Inside @rule, cell is the cell's state (a NamedTuple if there are several state variables), nbrs its neighbours' states, ctx its CellContext, and every parameter is available by name. The rule's value is the cell's next state. A model in continuous time declares @events begin ... end instead of @rule, whose value is the cell's transitions as rate => new_state pairs (an EventRule), and is solved with Gillespie or in discrete time.

julia> sir = @camodel SIR begin
           @states state::Symbol = :S ∈ (:S, :I, :R)
           @parameters β = 0.3 γ = 0.1
           @neighbourhood VonNeumann(1)
           @rule begin
               if cell == :S
                   bernoulli(ctx, 1 - (1 - β)^count(==(:I), nbrs), 1) ? :I : :S
               elseif cell == :I
                   bernoulli(ctx, γ, 2) ? :R : :I
               else
                   cell
               end
           end
       end;

julia> println(sir)

The problem of a CAModel on space. u0map maps state names to an initial value for every cell, an array the size of the space, or a function of the cell index (I -> ...); states it leaves out take their defaults. pmap maps parameter names to values; parameters it leaves out take their defaults. Both may be NamedTuples, Dicts or collections of name => value pairs. Initial values outside a state's domain raise InvalidStateError. Solver keywords (callback, saveat, ...) are stored with the problem, as for a problem built from a rule.
